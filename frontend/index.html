System Architecture & Engineering Decisions

Key architectural patterns implemented across the LedgerMesh clearing engine.

1. Strict Double Entry Invariants

Eliminates floating point drift and unbalanced money creation. Every transaction enforces balanced debits and credits in minor currency units (cents).

Σ Debits == Σ Credits ($0.00 variance tolerance)

2. Optimistic Concurrency Control (OCC)

Eliminates balance corruption under high concurrency without pessimistic locks. Version collisions trigger exponential backoff with full jitter.

CAS: WHERE id = :id AND version = :v

3. Tamper Evident SHA 256 Hash Chain

Every transaction record is cryptographically linked to the prior block hash. Any unauthorized edit breaks the downstream verification chain.

H(i) = SHA-256(H(i-1) || EntryData)

4. Distributed Idempotency Layer

Guarantees exactly once execution during network drops and client retry storms. Caches responses and rejects concurrent duplicate requests with HTTP 409.

Header: Idempotency-Key: <uuid>
